# OSG Sim v0.2.0 review and v0.2.1 fixes

Date: 2026-11-18. Input: the actual `OSG-Sim-v0.2.0-Source-and-Native-Test.zip`, SHA-256 `35caa9449275111c76a60798a0c2ffd805577fbcb26fdd401a2845a6929191eb`. Output: v0.2.1-dev source checkpoint.

The original 35 tests passed, but twelve additional regression tests failed against the original source. The corrected source passes 66 Node tests and the portable C++ serializer assertions. This establishes specific portable fixes. It does not establish a successful Windows DLL build/load, real Moon landing, physics non-perturbation, genuine OSG/LanceDB execution or browser/GPU acceptance.

## Scope and method

Reviewed every application/package module, native bridge and serializer, import and verification scripts, existing tests and acceptance claims. Investigated correctness, failure ordering, data provenance, concurrency, resource handling, numerical consistency, native lifecycle, observer isolation and reproducibility. Consulted primary runtime/protocol documentation and the exact pinned Metaverse and OSG source. No upstream repository was modified, no telemetry was sent to an external service, and no simulator execution was inferred from synthetic input.

The baseline reproduction is preserved in `before-regressions.log`: **0/12 pass, 12/12 fail** before corrections. Some tests contain several related assertions, so the first failing assertion establishes only that failure; additional checks are verified on the corrected source. Additional source-confirmed changes and remaining unmeasured risks are identified below.

## Findings and changes

Severity describes impact within this local development prototype, not an Internet-exposed deployment or a formal CVSS score.

| ID | Priority | Exact issue in v0.2.0 | Correction and evidence |
|---|---|---|---|
| F01 | High | `handleSample()` forwarded the caller's entire object. A physics-shaped frame could publish a `bridgeToken`, arbitrary fields and a producer-supplied `transportAuthenticated` claim to observer clients and state endpoints. | Build samples from an explicit allowlist; authentication is assigned from the connection context. Regression verifies removal of secrets/extras and a false authentication flag on direct unauthenticated ingestion. |
| F02 | High | Every line was independently queued before validation. Destroying the socket after malformed JSON did not cancel valid lines already queued behind it. | Sequential per-connection processing stops immediately on failure. Reproduced an invalid line followed by a valid sample in one write: original accepted the sample; corrected source accepts none. |
| F03 | High | The input byte limit bounded only the incomplete TCP string. Complete lines could produce an unbounded promise queue. Outbound writes ignored backpressure. | Pause ingress while its bounded chunk is processed. Slow WebSocket readers are disconnected rather than accumulating writes. Limit WebSocket observers to 64 and retain at most 100 error messages. Transport and backpressure regression tests pass. This does not bound historical journal growth; see remaining limits. |
| F04 | High | Serialization applied only inside one `DurableJournal` instance. Two instances/processes could both own the same file and independently extend the same hash-chain head. | Exclusive `events.journal.lock` writer ownership; second-writer regression fails closed. Failed startup releases owned resources. Lock files are never reclaimed merely because a timer expired. |
| F05 | Medium | Native time could regress inside an epoch; a vessel could repeat its step; frame changes and previously retired epochs could be accepted. | Validate sequence, step, per-vessel step, time and frame continuity. Reject retired runs and regressing epochs. Explicit time/vessel jumps in the native source begin a new epoch. Portable negative tests pass; actual SDK jump callbacks remain untested. |
| F06 | Medium | Run changes cleared the server cache but did not notify existing browser observers. Their old contact history and radial origin survived. | Publish a durable `SIMULATION_RESET`; observers clear run/epoch state and origin. Also detect a changed run/epoch from snapshots. Network and browser-independent reducer tests pass. |
| F07 | Medium | Replay mode still opened a native producer path and could mix recorded and native authority. | Refuse native input in replay mode, including the exported ingestion helper. Regression verifies accepted sample count remains zero. |
| F08 | Medium | Restart recovery treated a recovered contact position as an observer anchor, although it was not necessarily the original anchor. Runs without a contact/checkpoint could also lack durable evidence that their identity had been used. | No invented live anchor on restart. Journal the first run/epoch sample, then every 50 accepted samples. Refuse resuming any recovered native run; restart the simulator to establish a fresh runId. Initial-sample replay rejection and historical-journal retention tests pass. |
| F09 | Medium | `append(event)` retained a mutable caller object until the asynchronous write. Deduplication treated caller event IDs as global even though protocol identity includes run/epoch. | Snapshot validated input at append time; scope journal identities to run and epoch. Separate mutation and duplicate-ID regression tests pass. Existing on-disk records remain readable. |
| F10 | Medium | The physical sample blob omitted contact and angular velocity; missing orientation silently became the identity quaternion. The verifier therefore could not independently read contact from the asset. | Versioned 136-byte assets encode known/unknown flags, contact, optional orientation and angular velocity. Legacy 96-byte blobs remain readable with contact unknown. The native verifier now requires independently encoded `contact=true`. Importers stop inventing orientation. Round-trip and legacy/nonfinite tests pass. |
| F11 | Medium | Recorder receipts did not retain raw action bytes; run identity used the position file alone. The `LANDED` action could not be independently reconstructed from the retained binary position checkpoints. | Store exact `.pos` and `.atc` bytes in the asset store, bind both hashes into run identity and each imported receipt, retain action kind/detail/source line. Regression checks byte-for-byte recoverability. |
| F12 | Medium | Recorder/browser Hermite position used cubic interpolation while velocity used linear interpolation, so velocity was not generally the derivative of position. | Use the analytic cubic derivative in both paths. A simple case changes from incorrectly returning 0 m/s to correctly returning 1.5 m/s. Twenty-four independent SciPy position/derivative cases pass. |
| F13 | Medium | Recorder parsing did not reject unknown position frames or changing `STARTMJD`, allowing incompatible coordinates or time origins to be interpolated together. | Accept documented ECLIPTIC/EQUATORIAL position frames and require a consistent time origin/reference/frame. Preserve the first sample's authoritative metadata. Negative regressions and real recorder excerpt tests pass. |
| F14 | Medium | Determinant +1 alone allowed shear matrices through the basis check; quaternion conversion also normalized invalid rotations into plausible-looking output. | Require finite, orthonormal, determinant +1 rotations in JS and C++. Reject reflection/shear; validate quaternion dimensions and numbers. Independent SciPy quaternion/matrix cases and native serializer assertions pass. Native-to-renderer handedness remains an explicit integration task. |
| F15 | Medium | HTTP trusted arbitrary Host headers, and WebSocket Origin checks compared against that untrusted Host. Binding loopback alone did not reject rebinding-style hostnames. | Restrict bind addresses and Host to loopback names plus the actual local port; require the matching HTTP origin for browser WebSocket connections. Regression verifies a nonlocal Host receives 403. This is not simulator attestation. |
| F16 | Medium | Handwritten WebSocket handling assumed one TCP read represented a frame, ignored ping/pong and had an inconsistent 65,536-byte outbound boundary. | Parse split masked bounded control frames; reply to ping; reject application writes; encode the 64-bit length form at the exact boundary. Raw socket ping/pong, boundary and slow-reader tests pass. This intentionally remains a restricted read-only WebSocket endpoint. |
| F17 | Medium | The browser displayed the most recently received vessel and deduplicated events only by type/time/source. Another vessel could replace its sample or affect its contact display. | Select one vessel, optionally through `entity=`, filter native events by vessel/run/epoch and deduplicate by eventId. Causal API queries use the same selected vessel. Reducer tests pass; the new real-browser test remains blocked by Chromium startup. |
| F18 | Medium | A disconnected or reset observer could retain a live-looking sample; PlayCanvas could show a vessel proxy during a recorder gap. | Mark disconnected/behind samples stale, reconnect the read-only feed, reset event/origin state and hide the 3D proxy when authoritative data is unavailable. Reducer behavior is tested. Actual DOM/PlayCanvas behavior still requires browser/GPU execution. |
| F19 | Medium | Native blocking `send()` could prevent `stopWorker().join()` from finishing when a receiver stopped reading. HELLO also assumed one send transmitted all its bytes. JSON formatting ran inside the physics callback's queue lock. | Native source now uses nonblocking connect/send with deadlines, complete partial sends, a two-second shutdown drain deadline and worker-side serialization. This is a source correction, **not a verified Windows runtime fix**; Winsock/SDK build and shutdown tests are required. |
| F20 | Medium | Native sanitized vessel IDs replaced all unsafe characters with `_` and truncated names, merging distinct vessels. Reusing a vessel name after destruction also reused the stream identity. | Injective byte escaping, explicit length rejection and per-run vessel-lifetime IDs; deletion removes the lifetime association. C++ serializer collision/length assertions pass. SDK destruction/recreation behavior still requires Windows testing. |
| F21 | Medium | Stream serialization inherited global C++ locale and allowed integers outside JavaScript's exact range. C++ test assertions could disappear in Release builds. | Force the classic JSON numeric locale, enforce safe sequence/epoch/step and identifier limits, validate rotation matrices, and keep assertions active under `-DNDEBUG`. Direct g++ Release-style checks and the JS wire oracle pass. |
| F22 | Low | The covariance check used an absolute positive-pivot floor regardless of units and an absolute-tolerant symmetry check that could accept significantly asymmetric tiny covariances. Causality status added an arbitrary epsilon that could mark a signal received slightly early. | Require positive finite Cholesky pivots and scale-relative symmetry; compare query time directly with arrival. Small-unit and early-receipt regression tests plus 24 independent NumPy conditional covariance cases pass. No extreme-condition numerical stability guarantee is claimed. |
| F23 | Low | Trajectory comparison could print `status: PASS` for one sample while exiting with failure. It also did not explicitly require equal recording time spans. | Report FAIL for fewer than two comparisons and mismatched start/end times. One-sample regression passes. A real baseline/instrumented Metaverse comparison is still absent. |
| F24 | Low | OSG microsecond conversion could generate unsafe canonical integers, and its diagnostic commit-ID array grew indefinitely. | Reject unsafe microsecond values before graph publication and bound recent commit diagnostics. Negative regression passes. Genuine database behavior remains unverified. |

## Remaining issues and limits

1. **Native acceptance remains the main blocker.** Compile/link the modified DLL against the pinned x64 SDK; verify actual load, Moon contact, time/vessel jumps, vessel destruction/recreation and shutdown with a nonreading receiver. Read-only SDK calls still have callback/allocation/mutex overhead; physics non-perturbation has not been measured.
2. **Actual OSG persistence remains unverified.** The pinned graph source uses canonical safe integers, and its content hash excludes `observed_at`; a changing observation timestamp alone is therefore not evidence of a replay-idempotence bug. The adapter shape was checked against the actual source, but LanceDB durability, performance and reopen behavior still require `npm run test:osg` against a separately built checkout. The fake is not equivalent to that test.
3. **History growth is still unbounded.** The prototype loads journal history/deduplication and contacts into memory, offers a whole-journal HTTP response and reconciles historical graph events. Long-running/high-contact workloads need measured limits, paging/retention and incremental reconciliation. Bounded ingress and client writes do not solve historical storage growth. This source review is insufficient to assign a production player/entity capacity.
4. **A hash chain is not external tamper attestation.** It detects inconsistent retained bytes, but an attacker controlling the files can replace the whole chain or remove a suffix if no trusted prior head exists. OSG/ROD external anchoring is not implemented here. Shared bridge tokens likewise prove configuration, not genuine simulator origin.
5. **Not every physics sample is retained.** The journal records initial/periodic checkpoints and contact transitions; live intermediate samples are a feed. Complete trajectory reconstruction requires full recorder evidence or a designed complete durable stream. No acknowledged native-resume protocol exists; start a new run after service restart.
6. **Power-loss semantics require platform tests.** Files are synced and POSIX asset directories are synced before acknowledgment. Node does not expose the same portable directory flush on Windows, hard links depend on filesystem support, and abrupt-power tests were not run. A stale lock after a crash requires confirming all owners are stopped before manual recovery.
7. **Browser and GPU behavior are still open.** The new browser runner checks actual local transport and native-shaped reset/isolation behavior when Chromium can launch. It does not establish GPU rendering. The PlayCanvas contact field is a procedural illustration, not GPU/CPU parity with the mathematical 4D Gaussian oracle. Reference terrain/proxies are not physical surface geometry.
8. **Coordinate and observation models remain narrow.** The native global frame is not planet-centered terrain altitude; angular velocity is vessel-local. Recorder and native frames are not silently merged. A full renderer transform, moving-body origins, terrain/occlusion and physical sensors require explicit integration. The hypothetical stationary light-propagation endpoint does not restrict the shared observer telemetry feed to causally received information.
9. **Vessel removal has no dedicated wire event.** Lifetime IDs prevent accidental reuse, and stale-step display mitigates a stopped selected stream, but complete entity lifecycle synchronization is not implemented.

## Primary research sources

Reviewed sources support protocol/runtime/formula reasoning; actual defects above are established by the code and reproduction evidence, not by assuming documentation proves execution.

- [Node stream backpressure](https://nodejs.org/download/release/latest-jod/docs/api/stream.html): write return values and the difference between high-water thresholds and hard memory limits.
- [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html): masked client frames, control frames, partial transport delivery and extended payload lengths.
- [Winsock send](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-send) and [socket options](https://learn.microsoft.com/en-us/windows/win32/winsock/sol-socket-socket-options): blocking behavior and timeout semantics; the correction uses nonblocking operations instead of relying on an indefinite blocking send.
- [Node filesystem documentation](https://nodejs.org/api/fs.html): file-handle synchronization, exclusive open flags and file operations. A file API description does not establish tested power-loss semantics.
- [SciPy CubicHermiteSpline](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.CubicHermiteSpline.html) and [rotation matrix requirements](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.from_matrix.html): derivative consistency and valid rotation constraints. Numerical fixtures were generated using the locally installed versions, recorded in `fixtures/numeric-reference.json`.
- [Pinned Metaverse ModuleAPI](https://github.com/SpaceXpanse/Metaverse/blob/3264a944196c48a39d14beab7dafdd10c6918461/SpaceXpansesdk/include/ModuleAPI.h), [VesselAPI](https://github.com/SpaceXpanse/Metaverse/blob/3264a944196c48a39d14beab7dafdd10c6918461/SpaceXpansesdk/include/VesselAPI.h), [SpaceXpanseAPI](https://github.com/SpaceXpanse/Metaverse/blob/3264a944196c48a39d14beab7dafdd10c6918461/SpaceXpansesdk/include/SpaceXpanseAPI.h), and [FlightRecorder implementation](https://github.com/SpaceXpanse/Metaverse/blob/3264a944196c48a39d14beab7dafdd10c6918461/Src/SpaceXpanse/FlightRecorder.cpp): callback contracts, coordinate/angular-velocity semantics, module ownership and actual polar/recorder format. The existing polar conversion was consistent with the pinned reader and was not replaced.
- [Pinned OSG graph API](https://github.com/bellodox/OmniSpatialGraph/blob/bb087f2e5c4e208b5a6cc3000af9b2fe554ecb26/packages/core/src/graph.ts), [canonical hashing](https://github.com/bellodox/OmniSpatialGraph/blob/bb087f2e5c4e208b5a6cc3000af9b2fe554ecb26/packages/core/src/hash.ts), [contracts](https://github.com/bellodox/OmniSpatialGraph/blob/bb087f2e5c4e208b5a6cc3000af9b2fe554ecb26/packages/contracts/src/index.ts), and [Lance storage adapter](https://github.com/bellodox/OmniSpatialGraph/blob/bb087f2e5c4e208b5a6cc3000af9b2fe554ecb26/packages/storage-lance/src/index.ts): actual proposal/openStore/commit/verify shapes and safe-integer canonicalization.
- [PlayCanvas 2.24 GSplatContainer](https://github.com/playcanvas/engine/blob/v2.24.0/src/scene/gsplat/gsplat-container.js) and [GSplatFormat](https://github.com/playcanvas/engine/blob/v2.24.0/src/scene/gsplat/gsplat-format.js): source inspection confirms the used simple texture layout/API; it does not prove successful drawing.

## Reproduce and continue

Run `npm run verify:portable`, then `node scripts/stress-ingress.mjs`. Python/SciPy are only needed to regenerate the numerical fixture; normal tests consume its checked-in JSON and have no npm dependencies. Run `npm run test:e2e` on a host with Python/Playwright/Chromium. Follow `docs/WINDOWS_TESTING.md` for the remaining SDK/physics/OSG/GPU gates. Overall acceptance remains **PARTIAL**.
